# Open Problem Sources

Primary sources surveyed for the [Open Problems](/open-problems/) analysis. Each folder contains the original document (PDF or saved HTML) and a `SOURCE.md` recording the URL, year, and question count.

**Counts, reconciled 2026-08-05.** **Eight** of the nine sources below are surveyed. The paper (Appendix C) distils them into **17 problem types** — 8 clarified, 2 reframed, 7 scoped. The docs site carries 16 problem pages plus 3 source-summary pages; the paper's 17 is the number of record.

`icml_workshop_2026/` is **collected but unused.** It appears in exactly one place in the repo — the source table on the open-problems index — and no problem page or paper entry draws on it. Either mine it (its nine themes include "What is the right framework?" and "How should features/circuits be defined?", both squarely on this paper's territory) or drop the row. Do not cite it until it is used.

`orgad_barez_2026/` **is** used, and was missing from the paper's citation list until this date: the Training dynamics entry's "fine-tuning silently destroys circuits" is their catastrophic-forgetting-circuits result. Added as `orgad2026`, and the count went from seven to eight.

An earlier version of this README also claimed "22 problem types" and promised a `mapping.md` in each folder — the 22 predates the current taxonomy, and no `mapping.md` was ever written.

**Known gap.** Sharkey's *Sparsify* research agenda (`https://www.alignmentforum.org/posts/64MizJXzyvrYpeKqm`) is cited on three docs pages — decomposition-identity, resolution-completeness, training-dynamics — with no source folder here and no citation in the paper. Either add it as a tenth source or drop the site references.
